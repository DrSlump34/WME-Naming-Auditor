# Audit WME Naming Auditor — 26/07/2026 (v2.03 → v2.04)

Mesures faites **en live dans WME** (Coursan, contours dépt 11/30/34 chargés), pas déduites du code.

## ✅ Corrigé et prouvé en v2.04

### 1. Coupure à droite du panneau latéral — MAJEUR (signalé par l'auteur)

**La v2.03 n'avait corrigé qu'une cause secondaire** (`box-sizing` manquant sur les boutons). La vraie cause :

| | Largeur |
|---|---|
| `width` que WME pose **en dur** sur le `tab-pane` | **330 px** |
| Place réellement offerte par son conteneur avec la barre de défilement | **315 px** |
| ⇒ dépassement coupé sans barre horizontale | **13 px** |

Le conteneur `.tabContent--…` est en `overflow-y:auto` + `overflow-x:hidden` : dès qu'un onglet est assez long pour faire apparaître la barre verticale, la largeur utile tombe à 315 px, mais le contenu reste calé sur 330 → **coupé en silence**.

Reproduction : onglet **Affichage** (891 px de haut) → **41 éléments coupés**. Onglets Analyse (683 px) et Données (615 px) → intacts, faute de barre. C'est le « selon les onglets » de l'auteur.

**Correctif** : libérer la largeur (`width:auto`) sur toute la chaîne d'ancêtres jusqu'au conteneur qui coupe.
⚠️ Le poser sur le seul `pane` **ne suffit pas** : `registerScriptTab()` rend un DIV *interne*, c'est la `SECTION.tab-pane` au-dessus qui porte le 330.

**Vérifié** : 315 px et **0 débordement** sur les 3 onglets ; 330 px quand il n'y a pas de barre. Fluide, sans oscillation.

### 2. Import de partage : aucun contrôle de structure — MAJEUR

Les polygones d'un fichier **tiers** entraient tels quels. Conséquences :
- un `ring` absent → `a.ring.length` lève en pleine `renderAgglos` → **volet cassé** ;
- des coordonnées non numériques → zonage en **NaN** → **écarts faux** → **corrections à l'envers**.

C'est le risque contre lequel tout le reste du script se blinde ; l'import en était la seule porte ouverte. Les outils du dépôt de partage valident déjà, mais **c'est au client de se protéger** : rien ne garantit d'où vient le fichier.

**Correctif** : code INSEE valide (`\d{5}` ou `2[AB]\d{3}`), anneau **fermé** de ≥ 3 sommets, coordonnées finies et bornées, objet **reconstruit** (un fichier tiers n'impose pas ses champs), et le nombre d'entrées écartées est **affiché** — un import partiel silencieux serait pire que le défaut.

### 3. Sécurité (durcissements, aucun cas exploitable trouvé)

- **`esc()` était incomplet** : `>` et `'` non échappés. Aucun attribut n'est délimité par des apostrophes aujourd'hui (0 cas vérifié), mais les noms de rues/POI viennent de **Waze** et les étiquettes de polygones d'un **fichier tiers**. Corrigé aux cinq caractères. Vérifié : aucun usage de `esc()` hors contexte HTML, donc pas de régression d'affichage.
- **Import par URL non validé** : acceptait n'importe quel schéma. Désormais **https uniquement** (refus de `file:`/`data:`/`javascript:` et du HTTP en clair), contrôlé dans la fonction et non dans le bouton.

**Points déjà sains** (vérifiés, rien à faire) : les 41 interpolations HTML du fichier sont échappées ou portent des données internes ; `echecs` passe par `.map(esc)` ; le label de polygone importé est échappé ; les `${couleur}`/`${etiquette}` sont des placeholders de style OpenLayers, pas du HTML.
